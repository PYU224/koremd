# エディターの修正と確認手順

## 表示

- `<br>` と通常の改行は段落内の改行として、行の高さを文字サイズの1.6倍に維持。
- 空行（改行2つ）で分けた段落には、文字サイズの1.5倍の下余白を追加。
  16px設定なら行の高さ25.6px、段落間の追加余白24px。
- プレビュー内の文字にも選択したフォントを継承。コードは等幅フォントを維持。
- 長いURLなどを折り返し、コードブロックは横スクロールを維持。

## 不具合修正

- エクスポート時に、選択時の古いコピーではなく、現在編集中の本文と名前を渡す。
- 検索中の編集で検索結果を再計算して反映し、現在の検索位置を有効範囲に収める。
- IME確定時はtextareaの実際の値を読み取る。変換中は親への更新を抑止。
- Ionicがページをキャッシュしてアンマウントしない場合にも、離脱時に保存を実行。
- ファイル切り替え時の遅延処理を取り除き、切り替え後の検索状態をリセット。
- 作成・インポート時のIDにUUIDを使用し、同一ミリ秒での重複を防止。
- `build:plugin` を実際のリポジトリ内の配置に合わせて修正。

## 自動検証

```sh
npm ci
npm test
npx vue-tsc --noEmit
npm run build:all
```

8件の回帰テストで、段落と改行のHTML構造、サニタイズ、日本語IME確定、
ID重複防止、最新の内容のエクスポート、検索結果更新、Ionic離脱保存、ファイル切り替えを確認。
Ionicのライフサイクルはテスト内でモックしており、実機検証の代替ではない。

## Androidでの確認

以下を貼り付け、12px・16px・24pxの設定でプレビューを確認する。

```markdown
同じ段落の1行目<br>同じ段落の2行目
通常の改行も同じ段落

ここから別の段落

さらに次の段落
```

1. `<br>` より段落間の間隔が広いこと、フォント変更が本文に反映されること。
2. 本文と名前を編集してすぐ共有し、共有したファイルが最新の内容であること。
3. 日本語を変換確定し、プレビューと保存後の内容に反映されること。
4. 検索中に一致語を追加・削除して、件数と次／前の位置が更新されること。
5. 入力直後にAndroidの戻る操作で一覧へ戻り、同じ／別のファイルを開いて内容が混ざらないこと。
